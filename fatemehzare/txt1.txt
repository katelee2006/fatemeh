
Git چیست و چه کاربردی دارد؟
Gitیک سیستم کنترل نسخه یا Version Control System است که برای مدیریت تغییرات پروژه‌های نرم‌افزاری استفاده می‌شود. وقتی روی یک پروژه کار می‌کنیم، معمولاً فایل‌ها و کدهای مختلفی داریم که ممکن است بارها تغییر کنند. Git تغییرات انجام‌شده را ثبت و مدیریت می‌کند و به ما اجازه می‌دهد تاریخچه پروژه را داشته باشیم و در صورت نیاز به نسخه‌های قبلی برگردیم. یکی از کاربردهای مهم Git این است که مشخص می‌کند چه تغییراتی در پروژه انجام شده، چه کسی آن‌ها را انجام داده و چه زمانی انجام شده‌اند. Git همچنین برای کار گروهی بسیار مهم است، چون چند برنامه‌نویس می‌توانند روی یک پروژه کار کنند و تغییرات خود را مدیریت و با یکدیگر ترکیب کنند.
Gitبه صورت اصلی روی کامپیوتر خود برنامه‌نویس اجرا می‌شود و برای مدیریت نسخه‌های پروژه به اینترنت وابسته نیست. به همین دلیل حتی بدون اتصال به اینترنت هم می‌توان بسیاری از عملیات Git را روی پروژه انجام داد.
GitHub چیست و چه تفاوتی با Git دارد؟
GitHub یک پلتفرم اینترنتی برای میزبانی و مدیریت پروژه‌های نرم‌افزاری است که از Git استفاده می‌کند. GitHub به ما اجازه می‌دهد Repositoryهای خود را روی اینترنت قرار دهیم تا بتوانیم از هر جایی به آن‌ها دسترسی داشته باشیم، پروژه را با دیگران به اشتراک بگذاریم و به صورت گروهی روی آن کار کنیم. تفاوت اصلی این است که Git یک ابزار کنترل نسخه است، اما GitHub یک سرویس آنلاین برای میزبانی و همکاری روی پروژه‌های Git است. بنابراین Git و GitHub یکی نیستند، ولی معمولا در کنار یکدیگر استفاده می‌شوند.
Gitبیشتر مسئول مدیریت تاریخچه و تغییرات پروژه است، در حالی که GitHub امکاناتی مثل میزبانی Repository، همکاری تیمی، بررسی تغییرات، مدیریت پروژه و اشتراک‌گذاری کد را فراهم می‌کند.
Repository چیست؟
Repository یا مخزن، محلی است که پروژه و اطلاعات مربوط به نسخه‌های مختلف آن نگهداری می‌شود. یک Repository می‌تواند شامل فایل‌های برنامه، کدها، پوشه‌ها و تاریخچه تغییرات پروژه باشد.
Repository می‌تواند روی کامپیوتر شخصی برنامه‌نویس قرار داشته باشد یا روی سرویس‌هایی مانند GitHub میزبانی شود. در GitHub هر پروژه معمولاً در قالب یک Repository قرار می‌گیرد.

OOP کلاس، صفت و رفتار
برای هر یک از کلاس‌های زیر،  صفت (Property/Attribute)**و حداقل ۲ رفتار(Method) مناسب در نظر بگیرید. سعی کنید صفات و رفتارها با ماهیت واقعی آن کلاس ارتباط داشته باشند.

در برنامه‌نویسی شیءگرا یا OOP، کلاس یک الگو برای ساختن اشیا است. هر کلاس می‌تواند Property یا صفت داشته باشد که اطلاعات مربوط به آن شیء را نگهداری می‌کند و Method یا رفتار داشته باشد که کارهایی را که آن شیء می‌تواند انجام دهد مشخص می‌کند. برای مثال در کلاس Student می‌توان صفاتی مانند نام، شماره دانشجویی و رشته تحصیلی داشت و رفتارهایی مانند درس خواندن و مشاهده نمرات. برای کلاس‌های خواسته‌شده می‌توان این موارد را در نظر گرفت:
Customer: Name ،PhoneNumber ،Address / Register() ،PlaceOrder()
Student: Name ،StudentNumber ،Field / Study() ،ViewGrades()
Teacher: Name ،TeacherNumber ،Subject / Teach() ،GradeStudent()
Employee: Name ،EmployeeNumber ،Salary / Work() ،CalculateSalary()
Rectangle: Width ،Height / CalculateArea() ،CalculatePerimeter()
Square: Side ،Color / CalculateArea() ،CalculatePerimeter()
Dog: Name ،Breed ،Age / Bark() ،Run()
Cat: Name ،Color ،Age / Meow() ،Sleep()
HTTP چیست؟
HTTP مخفف HyperText Transfer Protocol به معنی «پروتکل انتقال ابرمتن» است. HTTP مجموعه‌ای از قوانین برای برقراری ارتباط بین Client و Server در وب است. وقتی کاربر از طریق مرورگر یا یک برنامه درخواست دریافت اطلاعات می‌کند، این ارتباط معمولا با استفاده از پروتکل HTTP انجام می‌شود.
HTTP مشخص می‌کند درخواست‌ها و پاسخ‌ها چگونه بین Client و Server منتقل شوند. در این ارتباط، Client یک Request ارسال می‌کند و Server در پاسخ یک Response برمی‌گرداند.
HTTP برای دریافت صفحات وب، ارسال اطلاعات، ارتباط با APIها و انتقال منابع مختلف در اینترنت استفاده می‌شود.
HTTPS چیست؟
HTTPS مخفف HyperText Transfer Protocol Secure است و نسخه امن‌تر HTTP محسوب می‌شود. HTTPS همان ارتباط HTTP را با استفاده از TLS رمزنگاری و ایمن می‌کند. هدف اصلی HTTPS این است که اطلاعاتی که بین Client و Server منتقل می‌شوند، در برابر شنود و دستکاری در مسیر ارتباط محافظت شوند. همچنین گواهی دیجیتال TLS به مرورگر کمک می‌کند هویت دامنه موردنظر را بررسی کند.
تفاوت HTTP و HTTPS
تفاوت اصلی HTTP و HTTPS در امنیت ارتباط است. HTTP به تنهایی ارتباط را رمزنگاری نمی‌کند، اما HTTPS از TLS برای رمزنگاری ارتباط استفاده می‌کند. به همین دلیل HTTPS برای وب‌سایت‌هایی که اطلاعات کاربران، حساب‌های کاربری، فرم‌ها، پرداخت‌ها یا سایر اطلاعات حساس را منتقل می‌کنند اهمیت زیادی دارد.

چرا بیشتر وب‌سایت‌ها از HTTPS استفاده می‌کنند؟
استفاده از HTTPS باعث می‌شود ارتباط بین کاربر و سرور در برابر بسیاری از حملات مرتبط با شنود و دستکاری مسیر ارتباط مقاوم‌تر باشد. همچنین مرورگرهای امروزی استفاده از HTTPS را برای امنیت کاربران جدی می‌گیرند.
HTTPS علاوه بر رمزنگاری، تمامیت داده‌ها و احراز هویت سرور را نیز فراهم می‌کند؛ یعنی داده در مسیر ارتباط راحت‌تر قابل دستکاری نیست و مرورگر می‌تواند بررسی کند که با دامنه موردنظر ارتباط برقرار کرده است.
چیست؟URL
URL مخفف Uniform Resource Locator است و به معنی «مکان‌یاب یکنواخت منابع» است. URL در واقع آدرس یک منبع در اینترنت است و به مرورگر یا یک برنامه می‌گوید برای دسترسی به یک منبع، از چه پروتکلی و در کجا استفاده کند. منابعی که با URL مشخص می‌شوند می‌توانند شامل صفحات وب، فایل‌ها، تصاویر، ویدئوها یا منابع مختلف یک وب‌سایت باشند.
یک URL را بررسی کنید و قسمت‌های مختلف آن را مشخص کنید.
یک URL می‌تواند از قسمت‌های مختلفی تشکیل شده باشد. مهم‌ترین بخش‌های آن شامل Protocol یا Scheme، Domain، Port، Path، Query و Fragment هستند. البته همه URLها الزاماً تمام این قسمت‌ها را ندارند.
Protocol مشخص می‌کند برای ارتباط با منبع از چه پروتکلی استفاده شود. Domain نام دامنه‌ای است که منبع روی آن قرار دارد. Port در صورت مشخص شدن، شماره پورتی را تعیین می‌کند که ارتباط از طریق آن انجام می‌شود. Path مسیر منبع موردنظر در سرور را مشخص می‌کند. Query برای ارسال پارامترها و اطلاعات اضافی به سرور استفاده می‌شود و Fragment معمولاً بخش مشخصی از یک صفحه را مشخص می‌کند. به طور کلی، URL مانند یک آدرس دقیق برای پیدا کردن یک منبع در فضای وب عمل می‌کند.
https://www.example.com/products?id=25⁠
GET چیست؟
GET یکی از متدهای HTTP است که معمولا برای دریافت اطلاعات از Server استفاده می‌شود. وقتی Client می‌خواهد یک منبع را دریافت یا مشاهده کند، معمولاً از GET استفاده می‌شود. در درخواست GET، اطلاعات مربوط به جست‌وجو یا فیلتر کردن منابع معمولا می‌تواند در قسمت Query URL قرار بگیرد. به همین دلیل داده‌های موجود در URL می‌توانند در تاریخچه مرورگر یا مکان‌های دیگر قابل مشاهده باشند.
GET معمولاً برای عملیاتی استفاده می‌شود که هدف آن دریافت اطلاعات است و نباید باعث تغییر ناخواسته در وضعیت Server شود.
POST چیست؟
POST نیز یکی از متدهای HTTP است و معمولا برای ارسال اطلاعات به Server و انجام عملیاتی روی داده‌ها استفاده می‌شود. اطلاعات ارسالی در POST معمولاً در قسمت Body درخواست قرار می‌گیرند.
POST می‌تواند برای ایجاد یک منبع جدید، ارسال اطلاعات فرم، ثبت اطلاعات یا انجام عملیات مختلف روی Server استفاده شود.
البته قرار گرفتن اطلاعات در Body به این معنی نیست که POST به خودی خود امن یا رمزنگاری‌شده است. اگر اطلاعات حساس ارسال شود، باید ارتباط از طریق HTTPS برقرار باشد.
چه تفاوتی بین GET و POST وجود دارد؟
تفاوت اصلی این دو در نوع استفاده و معنای درخواست است. GET بیشتر برای دریافت منابع و اطلاعات استفاده می‌شود، در حالی که POST معمولا برای ارسال داده و انجام عملیات روی Server استفاده می‌شود. در GET معمولا پارامترها در URL قرار می‌گیرند، ولی در POST داده‌ها معمولا در Body درخواست قرار دارند.
برای چه نوع درخواست‌هایی معمولا از POST استفاده می‌کنیم؟
همچنین GET معمولا برای درخواست‌هایی طراحی شده که نباید به صورت ناخواسته وضعیت Server را تغییر دهند، در حالی که POST می‌تواند باعث ایجاد یا تغییر اطلاعات در Server شود. بنابراین انتخاب GET یا POST فقط بر اساس مقدار اطلاعات نیست، بلکه به هدف و رفتار موردنظر درخواست بستگی دارد.
برای هرکدام یک مثال واقعی از یک وب‌سایت یا API ارائه دهید.
GET معمولا برای زمانی استفاده می‌شود که می‌خواهیم از یک وب‌سایت یا API اطلاعاتی را دریافت کنیم و چیزی را در سرور تغییر ندهیم. یعنی کاربر از سرور می‌خواهد یک سری اطلاعات را برایش بفرستد. مثلا در یک سایت فروشگاهی وقتی صفحه‌ی محصولات را باز می‌کنیم، مرورگر می‌تواند یک درخواست GET به سرور بفرستد تا اطلاعات محصولات را دریافت کند. یک نمونه‌ی واقعی هم API سرویس JSONPlaceholder است؛ مثلا با درخواست GET به آدرس مربوط به posts، اطلاعات پست‌ها از API دریافت می‌شود. در این حالت ما چیزی جدید ایجاد نمی‌کنیم، فقط اطلاعات موجود را از سرور می‌گیریم.
POST مثلا در یک سایت وقتی فرم ثبت‌نام را پر می‌کنیم و نام، ایمیل و رمز عبورمان را وارد می‌کنیم، اطلاعات فرم باید از مرورگر به سرور فرستاده شود. در چنین شرایطی معمولا از POST استفاده می‌شود. در همان JSONPlaceholder API هم می‌توان با یک درخواست POST، اطلاعات یک پست جدید را برای API ارسال کرد تا یک رکورد جدید ایجاد شود. 
JSON چیست؟
JSON مخفف JavaScript Object Notation است. JSON یک قالب متنی برای ذخیره و انتقال داده‌های ساختاریافته است که به دلیل ساختار نسبتا ساده و خوانایی بالا، در برنامه‌نویسی و مخصوصا ارتباط بین Client و Server بسیار استفاده می‌شود.
JSON داده‌ها را به صورت ساختارهایی مانند Object و Array نگهداری می‌کند و می‌تواند انواع مختلف داده مانند متن، عدد، مقدار منطقی، آرایه و داده‌های تو در تو را نمایش دهد. یکی از مهم‌ترین کاربردهای JSON در APIها است. وقتی یک برنامه با یک Server ارتباط برقرار می‌کند، اطلاعات می‌تواند در قالب JSON بین آن‌ها منتقل شود. JSON همچنین در بسیاری از زبان‌های برنامه‌نویسی قابل پردازش است و به همین دلیل برای ارتباط بین سیستم‌های مختلف بسیار مناسب است.
XML چیست؟
XML مخفف Extensible Markup Language است. XML نیز یک زبان متنی برای ذخیره، سازمان‌دهی و انتقال داده‌های ساختاریافته است.
XML اطلاعات را با استفاده از Tagها سازمان‌دهی می‌کند و برخلاف HTML، هدف اصلی آن نمایش ظاهر یک صفحه وب نیست؛ بلکه برای توصیف و انتقال داده طراحی شده است.
XML می‌تواند ساختارهای پیچیده و داده‌های تو در تو را نمایش دهد و امکاناتی مانند Attribute، Namespace و Schema دارد. به همین دلیل در برخی سیستم‌های سازمانی، نرم‌افزارهای قدیمی‌تر و بعضی سرویس‌های وب همچنان کاربرد دارد.
کاربرد JSON و XML چیست؟
هر دو برای ذخیره و انتقال اطلاعات ساختاریافته بین سیستم‌ها استفاده می‌شوند. مهم‌ترین کاربرد آن‌ها برقراری ارتباط بین برنامه‌ها، Client و Server و سرویس‌های مختلف است. در سیستم‌های نرم‌افزاری ممکن است یک برنامه اطلاعاتی را از یک Server درخواست کند و Server داده‌ها را در قالب JSON یا XML ارسال کند. بنابراین این دو قالب باعث می‌شوند سیستم‌های مختلف بتوانند اطلاعات را با یک ساختار مشخص با یکدیگر تبادل کنند.
تفاوت JSON و XML چیست؟
JSON معمولا ساختار ساده‌تر و کم‌حجم‌تری دارد و به همین دلیل در APIهای مدرن و برنامه‌های وب و موبایل بسیار رایج است. XML ساختار مبتنی بر Tag دارد و معمولا متن بیشتری برای نمایش همان اطلاعات نیاز دارد، اما امکانات ساختاری و کنترلی بیشتری ارائه می‌دهد. در نتیجه، JSON و XML هر دو برای انتقال و ذخیره داده هستند، اما نحوه نمایش و ساختار آن‌ها متفاوت است. انتخاب بین آن‌ها به نیاز پروژه، تکنولوژی مورد استفاده و استانداردهای سیستم بستگی دارد.
اطلاعات یک Student را یک بار با JSON و یک بار با XML نمایش دهید.
JSON
{
  "name": "Ali",
  "age": 20,
  "studentId": 101,
  "major": "Multimedia",
  "average": 18.5
}
XML
<Student>
    < Name > Ali </ Name >
    < Age > 20 </ Age >
    < StudentId > 101 </ StudentId >
    < Major > Multimedia </ Major >
    < Average > 18.5 </ Average >
</ Student >
